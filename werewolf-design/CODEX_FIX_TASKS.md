## 2. Codexに貼る文

```
products/werewolf/reference/ に、9人村の参照実装とテストがあります（依存なし。reference フォルダで npm test を実行すると25件が通ります）。
これを「正解の仕様」として、今の実装を点検して直してください。

■ 進め方
1. まず reference のコードとテストを読み、今の実装との違いを「重大／中／軽微」で一覧にして報告する
2. 重大と中のものから順に直す。参照実装をそのまま取り込んでも、同じ振る舞いになるよう自前のコードを直してもよい
3. reference/test の各テストに相当するテストを、今のプロジェクトのテストにも追加する
4. 既存のテストがすべて通ることを確認する

■ 特に確認すること
A. 情報の出し分け（reference/visibility.mjs）
   - AIに渡す文脈は aiContext と同じ範囲にする：伏せ札・他人の役職・心の声・特性の説明は入れない。密談と仲間の名前は人狼にだけ入れる
   - 観戦画面にブラウザへ送るデータは spectatorView と同じ範囲にする：決着前は役職と伏せ札を「送らない」（画面で隠すだけでは開発者ツールで見えてしまう）
   - 他のAIの発言は quoteSpeech のように1行の引用文字列にしてから渡す
B. ルール（reference/rules.mjs）
   - 同票 → 同票者だけで1回再投票 → それでも同票なら処刑なし
   - 勝利判定は処刑の直後と襲撃の直後の両方で行う。狂人は人間側に数える
   - 死亡者の票・自分への票は数えない。襲撃は人狼・死亡者を狙えない。人狼が1人でも襲撃が動く
   - 伏せ札が占い師・霊媒師・騎士のとき、その夜の処理は飛ばす
   - AIの応答から対象を1人に決められないとき（空・存在しない名前・複数の名前・時間切れ）は、候補からランダムに選んで試合を止めない
C. 隠し特性（reference/traits.mjs）
   - 確率判定はコードで行い、シードを固定したテストを書く
   - 発言前の指示（directivesFor）と、発言後の表示用の加工（postProcess）に分ける
   - 投票・襲撃・護衛などの構造化データには特性を適用しない
   - 野獣先輩の数字置換は「3番」「2日目」「2票」「No.7」を壊さない
   - 寝落ちで切れた発言は、切れた後の文がそのまま広場に出る。CO や占い結果は、広場に出た文に含まれている場合だけ記録する（切れたら次の発言で言い直す）
   - ヒロユキとリノの特性は1試合1回まで
D. サーバーと秘密情報
   - APIキーがブラウザ側のコードや Git に入るファイルに含まれていないか。.env は .gitignore に入っているか
   - ローカルサーバー（127.0.0.1:3079）が 0.0.0.0 など外部からアクセスできるアドレスで待ち受けていないか
   - 利用枠の上限や通信エラーで止まったとき、途中から再開できるか

■ 最後に
実AIで3試合回し、試合ごとに「勝った陣営・日数・伏せ札・隠し特性の発動回数・エラーの有無」を表にして報告してください。
```

## 3. 参照実装の中身

| ファイル | 内容 |
|---|---|
| `reference/rules.mjs` | 配役（人狼2固定＋伏せ札1枚）、夜0のお告げ、勝利判定、投票の集計と同票処理、襲撃、護衛、壊れた応答の扱い |

| `reference/traits.mjs` | 9人の隠し特性。発言前の指示と発言後の加工 |
| `reference/rng.mjs` | シード付き乱数 |
| `reference/test/` | 上の仕様を確かめるテスト25件 |

### 決めておいた仕様（相談なしで決めたもの）
- **同票が2回続いたら処刑なし**（一般的なルール）
- **観戦画面に人狼の密談を出す**：観戦者に人狼2人がわかっても、残り8枚の内訳は推測できないので、伏せ札は漏れません。役職の一覧と伏せ札は、これまでどおり決着後に公開します
- **寝落ちで切れた占い結果は、その発言では記録しない**：他のAIも切れた文しか読めないため、記録と表示をそろえました
